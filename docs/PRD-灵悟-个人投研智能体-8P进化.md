## 1. Summary

灵悟已经具备成为一名个人投研智能体的坚实底座：耐久任务引擎、多 Agent 空间、观察列表、市场简报、投资组合、论点周检、账户级记忆、技能与连接器、浏览器与沙箱。底座在，缺的是"像一个一直懂你的投研同事"。

本文参考"8P 原则"对灵悟做了逐项体检：**八条中四条只做到一半（像人、主动、克制、懂你），两条有结构性缺位（一直在线靠云进程但没有设备触达、隐私可靠但缺少动作审计与敏感确认）**。对照"模型决定下限、context 和闭环决定上限"，灵悟当前的重心仍在补"下限"（更多研究动作），而决定上限的**投研 context 闭环**——研究产物 ↔ 论点 ↔ 追踪 ↔ 复盘——尚未真正咬合。

本文档不是新增功能的堆叠，而是给出一份**进化路线图**：把灵悟从"能做研究的工具"升级为"一直在线、懂你、克制、能把研究闭环办完的投研同事"。所有改进项按优先级组织（P0 为体验与闭环支柱，P1 为触达与信任，P2 为上限与自进化），并复用现有架构（TaskWorker、Hindsight、通知收件箱、Agent/频道体系），避免推倒重来。

## 2. Background and Evidence

### 2.1 文章核心观点提炼

| 维度 | 文章主张（原文要点） | 对本项目的启示 |
| --- | --- | --- |
| 定义 | Personal Agent 是一种生活方式；"任何事，默认先交给它" | 灵悟不应停在"被叫才干活"的工具，应成为用户投研的默认入口 |
| 8P 原则 | 像人、触手可及、一直在线、懂你、主动、克制、能办完、隐私可靠 | 逐条对照即本文第 4 章诊断表 |
| 上限 | Context 价值随组合指数增长（2ⁿ）；模型决定下限，**闭环决定上限** | 把研究→论点→追踪→复盘串成闭环，比堆更多研究动作更重要 |
| 产品 | 不设计 UX，设计 AX；把产品内每个操作镜像成 agent 命令；不做定制 UI | 研报、简报、组合这些用户可见操作，也应成为 agent 可调用的能力 |
| 技术 | 交互与执行分离（秒回"好，我去办"）；Runtime/Harness/Sandbox/Filesystem 分离；context 分层加载；记忆即知识图谱、即推荐问题；两级触发（规则过滤 + agent 按需判断）；自我迭代（上报→修改→回放验证→灰度）；隐私画一条清楚的线 | 灵悟已有 TaskWorker 异步执行、分层记忆、app 内通知，是天然的落地载体 |

### 2.2 灵悟现状基线（与 8P 的体检摘要）

| 原则 | 现状判断 | 关键证据 |
| --- | --- | --- |
| PERSONABLE 像人 | 部分 | 有对话、任务中心、产物卡片，但长任务体验是"等待"而非"秒回 + 后台办"；交互风格仍偏报告体 |
| PROXIMATE 触手可及 | 部分 | Web/移动端即时可用；但"长任务秒回确认"未成型；设备级触达缺失 |
| PERSISTENT 一直在线 | 部分 | 耐久任务、云端 Worker 常驻已具备；缺设备推送，用户关闭 App 即失联 |
| PERSONALIZED 懂你 | 部分 | 记忆系统（Hindsight）已按 Agent 隔离并支持结构化字段，但语义召回未接入对话主链；无投研画像 |
| PROACTIVE 主动 | 部分 | 已有定时简报、价格提醒、网页监控；触发以规则/定时为主，无两级过滤，会吵 |
| PRUDENT 克制 | 缺失 | 无"是否值得打扰"的判断层；无信息流机制收纳次要提醒；简报按 UTC 整机触发，不考虑用户时区 |
| PRODUCTIVE 能办完 | 部分 | 任务可办完并回执；但研究产物是"一次性交付"，未自动转成持续跟踪 |
| PRIVATE 隐私可靠 | 部分 | 凭据加密、账户隔离、可遗忘记忆已具备；缺敏感动作确认、操作审计、连接只读/可写分级 |

详细逐项诊断见 [第 4 章](##-4.-现状诊断：8P-逐项体检)。

## 3. Goal and Success Criteria

### 3.1 产品目标

把灵悟从"能做研究的工具"升级为"**一直在线、懂你、克制、能把研究闭环办完的投研同事**"，形成"研究 → 论点 → 追踪 → 复盘 → 下次研究更懂你"的飞轮。

### 3.2 成功标准（北极星 + 关键指标）

**北极星指标：周有效触碰数**——用户每周真实点击/展开/采纳（而非仅收到）的 Agent 主动提醒与简报条数。该指标界定"克制的主动"：提醒要少而准，被用户点开才算数。

| 指标 | 当前基线 | 目标值 | 衡量方式 |
| --- | --- | --- | --- |
| 周有效触碰数 | 未统计 | ≥ 5 条且推送接收率（点开/收到）≥ 40% | 通知行为埋点 |
| 长任务"秒回确认"延迟 | 无此体验 | ≤ 1.5s 收到"好，我去办"回执 | 交互层延迟采样 |
| 论点自动回检的判定准确率 | 仅"待人工确认" | 自动判定与人工复核一致率 ≥ 70% | 论点状态变更日志 |
| 研究任务的分身率（研报→自动生成跟踪计划） | 0 | ≥ 50% | 研报产物统计 |
| 记忆在对话首轮命中的比例 | 未接入 | ≥ 60% 的研究任务自动带上画像上下文 | 对话 trace |
| 敏感动作确认覆盖率 | 0 | 100%（外发/写入类动作） | 审计日志 |

## 4. 现状诊断：8P 逐项体检

> 判定标准：✅ 完整 / 🔶 部分 / ❌ 缺失。改进映射到 [第 5 章](##-5.-Functional-Requirements) 的编号需求。

| 原则 | 判定 | 现状 | 差距（改进需求映射） |
| --- | --- | --- | --- |
| 1. PERSONABLE 像人 | 🔶 | 对话 + 任务中心 + 产物卡片已具备 | 交互回复仍偏报告体；长任务是"等待"而非"秒回 + 后台办" → **R1** |
| 2. PROXIMATE 触手可及 | 🔶 | Web/App 即时可用，移动端抽屉导航完善 | 秒回体验缺失；无系统级通知触达 → **R1、R5** |
| 3. PERSISTENT 一直在线 | 🔶 | 耐久任务、云端 Worker 常驻 | App 关闭即失联，需设备推送与日程感知 → **R5** |
| 4. PERSONALIZED 懂你 | 🔶 | Hindsight 记忆按 Agent 隔离，四类结构化字段 | 语义召回未进对话主链；无投研画像（组合/论点/偏好驱动） → **R3** |
| 5. PROACTIVE 主动 | 🔶 | 简报、价格提醒、网页监控、论点周检 | 纯规则/定时触发，无两级过滤 → **R2** |
| 6. PRUDENT 克制 | ❌ | — | 无"值不值得打扰"判断层；无信息流收纳次要提醒；调度忽略用户时区与交易日 → **R2、R5** |
| 7. PRODUCTIVE 能办完 | 🔶 | 任务可办完、回执、审批 | 研报一次性交付，未转持续跟踪；操作未镜像为 AX 命令 → **R4、R7** |
| 8. PRIVATE 隐私可靠 | 🔶 | 凭据加密、账户隔离、可遗忘记忆 | 缺敏感动作确认、操作审计、连接授权分级 → **R6** |

**结构性结论**：灵悟的短板不在"能力多少"，而在**主动性与懂你的分寸**（R2、R3）与**闭环咬合**（R4）。这两块正是文章所说"决定上限的 part"。

## 5. Functional Requirements

> 优先级：P0=本阶段必须；P1=下一阶段；P2=上限储备。每条需求复用现有模块（TaskWorker、Hindsight、通知收件箱、Agent/频道体系、产物体系），不新建孤立系统。

### R1（P0）像人、秒回：交互与执行分离体验化

- **用户故事**：作为投资者，我对 Agent 说"研究一下宁德时代，顺便盯下它的财报日期"，我希望它立刻回我"好，我去办"，而不是让我盯着转圈图标等几分钟；中途我想插一句"先只看利润率"也能打断。
- **功能行为**：
  - 长任务派发时，交互层**立即回执**（"好，我去办" + 一句话计划摘要），任务进入既有任务中心，进度仍由任务中心与运行态标签承载。
  - 交互回复采用**快而便宜**的模型路径（如 DeepSeek-Flash 级），并施加"短、直接、说人话"的回复风格约束（Prompt 层）；深度研报、简报、图表等长交付一律收敛为**产物卡片**（已有产物体系），正文只给摘要与追问入口。
  - 允许在任务运行中**打断/插话**：新指令进入对话流，不影响后台任务；任务最终仍回到对话交付。
- **技术需求**：在现有 CopilotKit 对话层与 TaskWorker 之间补齐"交互回执路由"；为交互侧设置独立的轻量模型配置（复用个人模型连接机制）；产物卡片沿用现状，不改渲染层。
- **验收标准**：
  - 长任务派发后 ≤ 1.5s 收到回执文案，任务同时在任务中心可见。
  - 长交付不进入对话正文（仅产物卡片 + 摘要）。
  - 任务运行中可连续下发 2+ 条指令各就其位，不互相覆盖。

### R2（P0）克制的主动：两级触发与事件监控升级

- **用户故事**：作为投资者，我不希望 Agent 把行情波动、新闻、公告什么都推给我；我只在"真正改变我安排或论点"时被提醒，其余淡淡的放进一个信息流，等我去翻。
- **功能行为**：
  - **两级触发**：新增事件接入层（第一级）先被低成本规则快速过滤（优先级、标的匹配、阈值、去重），通过后再进入低成本 agent 判断层（第二级）：结论为"重要→推送 / 一般→进信息流 / 不打扰→记日志"，保留决策记录可追溯。
  - **事件源升级（P0 可选）**：优先接入事件日历（财报发布日、经济数据发布、央行会议）、公告流（巨潮/交易所/EDGAR）、评级与目标价调整。当前周期轮询的行情/网页监控保持不动，作为兜底。
  - **克制信息流**：新增"今日概览/信息流"视图（桌面能力侧栏与移动端抽屉可放置），收纳"一般重要"提醒；重要提醒才走通知收件箱实时推送。
  - **负反馈闭环**：信息流/通知卡片提供"这类少推点"入口，选择即写入投研画像偏好（联动 R3），可持续冷却。
- **技术需求**：在 Worker 维护循环 + TaskWorker 基础上增加"事件过滤 + agent 判级"流水线；判级调用走轻量模型；事件去重沿用 24h 去重机制扩展为按事件类型去重。
- **验收标准**：
  - 提醒接收率的定义可量化（点开/收到），周有效触碰数可用后台数据核验。
  - 未推送但真实发生的事件，可在信息流中补齐，不遗漏关键信息。
  - 用户点"少推点"后同类事件推送在 2 周期内明显下降。

### R3（P0）懂你：投研画像与记忆闭环

- **用户故事**：作为长期价值投资者，我希望 Agent 记得我重仓新能源、偏好 ROE>15%、正跟踪宁德时代 Q4 财报；我每次让它研究公司，它都自动带上这些上下文，而不是每次从零开始。
- **功能行为**：
  - **投研画像**：由组合、观察列表、论点库、记忆自动推导并持续修正：持仓结构、关注赛道/风格、风险偏好、常用数据需求。画像无需用户配置（默认从现有数据组装），并支持主动修正入口。
  - **记忆召回接入对话主链**：对话与研究任务发起时，按"此刻最该被想起来"召回相关记忆与画像（复用 Hindsight recall + 关键词兜底），注入上下文并可在回复中溯源展示。
  - **论点自动回检升级**：从"仅标记待人工确认"升级为**证据绑定 + 自动判定**——绑定核心假设对应的可观测信号（股价阈值、新闻关键词、财报字段），自动判为：成立 / 待验证 / 受威胁 / 不成立；状态变更即触发通知（经 R2 判级）。
  - **决策日志闭环**：买入/卖出笔记自动关联论点与标的，形成"决策时间线"，支持季度/年度自动复盘报告（复用简报/报告产物体系）。
- **技术需求**：画像作为 Hindsight 记忆的一种类型写入（extend 记忆 schema）；召回注入点选在对话上下文组装处；论点回检复用 TaskWorker 定时任务，扩展自动判定逻辑（不伪造结论：判定依据必须绑定证据）。
- **验收标准**：
  - 研究任务首轮即携带画像/记忆上下文 ≥ 60% 的会话可核验。
  - 论点自动判定与人工复核一致率 ≥ 70%（持续抽样）。
  - 决策日志时间线在标的详情可见，支持一键导出复盘报告。

### R4（P0）能办完：研究到跟踪的闭环咬合

- **用户故事**：我让它研究一只股票，它给了研报，但我希望它不只是一次性交付——把研报里的关键假设、催化剂、财报日期自动变成我持续跟踪的东西，到期提醒我验证。
- **功能行为**：
  - **研报→跟踪计划**：深度研报（六段式报告）生成后，自动派生跟踪计划：关键假设（论据）、关键指标（如 ROE、净利率）、催化剂（财报日、行业事件）、估值区间，自动落入监控体系与论点库。
  - **产物即操作**：研报/简报/组合页内操作（重新研究、更新假设、盯住日期）以 AX 方式暴露给 Agent，用户可用自然语言触发同等的产物操作（"把 A 股这块重新拉一遍"）。
  - **技能沉淀**：把"一次办成"的投研流程（如研究方法、拆数流程）沉淀为可复用技能（复用账户级/频道技能体系），二次执行时更快更稳。
- **技术需求**：扩展研报产物 schema 增加 `tracking_plan`；监控规则与论点之间建立引用链（复用现有 rule/task 链接机制）；技能沉淀走现有技能编辑器，不强依赖执行脚本。
- **验收标准**：
  - 研报生成后自动产出跟踪计划的比率 ≥ 50%。
  - 跟踪计划中的财报日期能进入 R2 事件层并在到期前提醒。
  - 沉淀技能可在另一标的上复用。

### R5（P1）一直在：设备推送、时区与交易日历调度

- **用户故事**：我希望早上 8 点（我所在时区）打开手机就看到今天简报，休市日不要推噪音；我在外面也能收到持仓异动推送。
- **功能行为**：
  - **设备推送**：补齐 APNs/FCM（移动端）推送通道，通知收件箱与设备推送双写；推送文案走双语文案（沿用 runtimeLabelBilingual）。
  - **时区与交易日历**：简报与事件提醒按用户时区（从账户/设备推断）与交易日历（休市日静默）调度，替代当前固定 UTC 整点。
  - **召回治理**：设备推送仅经 R2 判级为"重要"的事件，其余留在信息流。
- **技术需求**：新增推送凭证存储与下发队列；调度时间换算复用现有 date-time 工具；交易日历以配置驱动（先内置主要市场节假日，手动维护）。
- **验收标准**：
  - 简报在用户所在时区指定时刻前送达（含设备通知）。
  - 休市日不推行情类提醒。
  - 设备推送点击可由 R2 统计进周有效触碰数。

### R6（P1）靠得住：敏感动作确认与操作审计

- **用户故事**：把持仓和论点交给 Agent 后，我要知道它替我做过什么；涉及对外动作（分享、发邮件、变更设置）之前，它必须问我。
- **功能行为**：
  - **敏感动作确认**：外发类（分享链接、邮件草稿发送）与写入类（变更组合、删除数据）动作先弹确认（复用现有审批/回执机制）。
  - **操作审计**：落一个 Agent 动作日志（做了什么、何时、作用于哪个标的/连接器、结果），可在设置页查看并支持撤回（删除类动作）。
  - **连接授权分级**：连接器授权区分"只读/可写"，逐项可撤销（复用现有连接器管理，补充授权粒度）。
  - **隐私线明确**：持仓/论点为最敏感数据，声明只在账户内处理与存储；模型提供方不接触用户密钥（现状已满足，文档化）。记忆"忘记"入口保留。
- **技术需求**：审计存现有 records/审计表；确认流复用审批回执组件；连接器授权模型增加 scope 字段。
- **验收标准**：
  - 外发/写入类动作 100% 经过确认。
  - 设置页可查最近 30 天操作日志并可对可逆操作执行撤回。
  - 连接器均支持只读/可写切换且即时生效。

### R7（P2）上限：以标的为中心的知识图谱与自进化

- **用户故事**：我希望它把"关于宁德时代，我已经知道的"一次性组织出来：我的论点、笔记、历史研报、记忆、持仓、最近事件，像一个研究员的工作底稿。
- **功能行为**：
  - **标的中心知识图谱**：以标的（symbol）为实体，关联论点、笔记、报告、记忆、监控规则、持仓、事件，形成可检索、可追问的"标的档案"（增强现有标的详情页）。
  - **效果反馈回流**：研报/简报提供点赞/点踩与原因选择，反馈回流为 prompt/数据源的调优数据（对应文章"自己发现问题、自我迭代"，先用轻量人工回标，暂不做自动改 harness）。
- **技术需求**：在 Hindsight 图谱能力基础上建立标的实体索引与关联边；反馈落表并出调度报告。
- **验收标准**：
  - 标的档案可在一次追问内列出该标的相关记忆/论点/报告/事件。
  - 反馈数据每月可产出一份"低分研报原因分布"报告，驱动下次迭代。

## 6. 数据模型变更（增量）

> 原则：全部复用现有 records/JSONB 快照模式，仅新增字段与类型，不做迁移重建。

| 新增/变更 | 说明 |
| --- | --- |
| `profile`（画像） | Hindsight 记忆新类型：投研画像（持仓推导、赛道、风格、风险偏好、负反馈偏好） |
| `tracking_plan`（跟踪计划） | 研报产物扩展字段：关键假设、关键指标、催化剂、估值区间、关联监控规则 |
| `thesis_evidence`（论点证据） | 论点记录扩展：绑定的可观测信号（阈值/关键词/财报字段）、最近一次自动判定与依据 |
| `event_feed`（事件流） | 事件接入与判级流水：事件类型、标的、判级结论（push/feed/silent）、24h 去重键、判级依据 |
| `agent_action_log`（动作审计） | agent 对外动作记录：时间、动作、对象、确认状态、结果、可撤回性 |
| `connector_scope`（授权粒度） | 连接器授权增加只读/可写 scope |
| `push_token`（设备推送） | 设备推送凭证（APNs/FCM）、所属账户、失效状态 |

## 7. Acceptance Criteria

### 7.1 Happy Path

- [ ] 用户对 Agent 说"研究一下宁德时代并盯财报日期"：1.5s 内回执，任务后台执行，研报以产物卡片交付，并自动生成跟踪计划与财报日期提醒。
- [ ] 用户首页/顶部出现"今日概览"：重要提醒优先，次要进信息流；用户点"这类少推点"，同类推送两个周期内下降。
- [ ] 用户发起"研究比亚迪"：对话自动带上其投研画像（重仓新能源、偏好 ROE>15% 等）且可溯源。
- [ ] 持仓异动达到"重要"判级时，设备推送到达且计入周有效触碰数；休市日不推行情噪音。
- [ ] 用户外发分享或变更组合设置前出现确认；设置页可查 30 天操作日志并撤回可逆操作。

### 7.2 Error Path

- [ ] 事件源不可用时，降级为原有周期轮询 + 提醒"数据延迟"，研究/回检不中断。
- [ ] 判级模型超时/失败时默认"进信息流"而非丢弃，保证不遗漏。
- [ ] 推送通道失败时，通知完整保留在收件箱，不影响召回治理。

### 7.3 Edge Cases

- [ ] 用户横跨多个时区/多市场（A/H/美股）时，调度按默认市场与账户时区各自生效。
- [ ] 论点判级对象退市/停牌时，标为"受威胁-缺乏数据"并说明原因（沿用现有逻辑扩展）。
- [ ] 用户画像与用户显式偏好冲突时，显式偏好优先并记录一致处理规则。

## 9. Risks and Open Questions

### 9.1 风险

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 主动推送误报频发反而流失信任 | 高 | 北极星守"周有效触碰数"，两级判级默认保守（宁可进信息流不推送） |
| 论点自动判定错误被用户误当结论 | 高 | 判定必须绑定证据、状态可人工覆盖，UI 标注"自动判定，可修正" |
| 语义召回接入对话引入噪声 | 中 | 召回结果限条数 + 注入前过滤；画像上下文异常时回落基线 |
| 事件源接入成本高 | 中 | P0 仅接事件日历与公告流；长尾继续用周期轮询兜底 |
| 设备推送合规（隐私协议） | 中 | 推送仅承载判级结果，不携带持仓明细原文 |

### 9.2 Open Questions

- [ ] 两级判级中的"低成本 agent"是否复用交互侧轻量模型，还是固定专用模型？
- [ ] 交易日历先覆盖哪些市场（A股/港股/美股三市场节假日），维护机制是配置驱动还是数据源？
- [ ] 投研画像是否允许用户导出（可携带性）？
- [ ] 效果反馈回流的第一优先级：研报质量评分 vs 判级准确性评分？
- [ ] "标的中心知识图谱"是否与标的详情页合并为一个入口，还是独立视图？

## 10. 总结

灵悟的底座已经超过绝大多数个人 AI 投研产品。本次进化的核心不是"再加什么功能"，而是**把 8P 里最影响上限的三件事做对**：

1. **克制的主动（R2）**：把"提醒"从规则阈值升级为"两级判级 + 信息流"，配合北极星"周有效触碰数"。
2. **懂你的闭环（R3、R4）**：记忆/画像进入对话主链；研报自动变成持续跟踪计划，让研究真正"办完、并接着办"。
3. **像人与触达（R1、R5）**：秒回回执 + 设备推送 + 时区/交易日感知，让"一直在线"成为真实体验。

隐私（R6）与图谱、自进化（R7）是信任与上限的长期肌肉投资，随架构演进自然生长。
