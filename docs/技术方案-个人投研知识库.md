# 技术方案 — 个人投研知识库（可检索）

> 关联 PRD：`docs/PRD-LingWu-个人投研智能体.md`（P2「投资知识库」）｜ 状态：设计稿
> **核心决策**：复用现有「records 权威存储 + Hindsight 语义引擎」两层架构，**不新建向量数据库**。知识库 = 记忆系统的"长文档版"。

---

## 1. 现状与设计原则

### 1.1 已有的可复用资产

| 资产 | 位置 | 现状 |
| --- | --- | --- |
| 研报存储 | `apps/server/src/engine/research.ts`（`research_reports`，六段式 sections） | 已按 owner 持久化 |
| 投资笔记 | `apps/server/src/engine/notes.ts`（`notes` / `thesis_checks`） | 已按 owner 持久化 |
| 简报/产物 | `agent-artifacts` / `market_briefings` | 已持久化 |
| 语义引擎 | `apps/server/src/engine/hindsight.ts`（`retain`/`recall`/`deleteDocument`） | 已接入写入链路，四路检索（语义/BM25/图/时间） |
| 记忆本体 | `memories`（`AgentMemoryV2`） | 短文本、按 `agentId` 隔离 |

### 1.2 知识与记忆的边界

| 维度 | 记忆（memories） | 知识库文档（knowledge docs） |
| --- | --- | --- |
| 内容形态 | 一句话/摘要（fact、thesis、decision…） | 长文档正文（研报全文、笔记全文） |
| 隔离粒度 | `owner:agentId`（Agent 私有） | `owner`（账户私有，跨 Agent 共享） |
| 消费场景 | 对话/任务上下文召回 | 检索面板、深度研究引用、复盘 |
| bank 命名 | `{owner}:{agentId}` | `{owner}:kb`（单一知识库 bank） |

> 两者物理上共用同一个 Hindsight 引擎，**通过 bank 隔离**，互不串味，运维零新增组件。

## 2. 总体架构

```
┌───────────────────────────────────────────────────────────────┐
│ 前端 (apps/mobile)                                             │
│  知识库面板（搜索框 + 标的/类型/时间筛选 + 结果列表 + 跳转详情）  │
└───────────────────────────────▲───────────────────────────────┘
                                │ POST /api/knowledge/query
┌───────────────────────────────┴───────────────────────────────┐
│ Server — KnowledgeBaseService（新增，编排层）                    │
│   index()  upsert()  remove()  query()  reindex()  stats()     │
│        │                                    │                  │
│        ├─► 写入挂载点（增量，见 §5）            │                  │
│        │    research.ts / notes.ts / files.ts │                  │
│        │                                      │                  │
│        ├─► 权威存储：records（research_reports │                  │
│        │    / notes / agent-artifacts，事实源）│ 语义检索          │
│        └─► 检索索引：Hindsight bank `{owner}:kb`◄─┘               │
└────────────────────────────────────────────────────────────────┘
   PGlite / Supabase records 表（唯一事实源）    Hindsight（仅检索索引）
```

**设计原则**：

1. **权威存储不变**：研报/笔记仍在 `records` 原表读写，知识库只是"额外建立一个检索索引"，不迁移、不复制业务逻辑。
2. **索引可重建**：Hindsight bank 可由 records 全量重建（`reindex`），丢索引不丢资产。
3. **双写幂等**：`knowledge_doc.id = sha256(owner:kb:{sourceKind}:{sourceId})`，重建/更新天然去重。
4. **检索结果回链**：召回命中只返回元数据 + 分数 + `sourceId`，正文展示仍走原记录/原报告，保证"看到的就是库里那份"。

## 3. 数据模型（`packages/domain/src/knowledge.ts` 新增）

```ts
export type KnowledgeSourceKind =
  | "research_report"  // 六段式研报（research_reports）
  | "note"             // 投资笔记（notes，含 THESIS）
  | "briefing"         // 每日市场简报（market_briefings）
  | "artifact"         // 对话/任务产物（agent-artifacts）
  | "pdf";             // 手动导入的研报/财报 PDF（经 PDF 管线解析）

export interface KnowledgeDoc {
  id: string;               // sha256(owner + sourceKind + sourceId)，幂等键
  owner: string;            // 账户隔离（RLS 同源）
  sourceKind: KnowledgeSourceKind;
  sourceId: string;         // 回链 records 原记录
  title: string;            // 报告标题 / 笔记标题
  content: string;          // 检索正文（Markdown）。→ Hindsight retain 的原文
  symbolCode?: string;        // 归一化标的（600519.SS / AAPL），写入时 normalizeYahooSymbol
  market?: "US" | "CN" | "HK";
  // ── 结构化检索字段（供过滤，不参与向量）──
  noteType?: "BUY_REASON" | "SELL_REASON" | "RESEARCH" | "THESIS";
  rating?: string;          // 看多/看空…
  targetPrice?: string;
  thesisStatus?: string;    // ACTIVE / VALIDATED / …
  tags?: string[];
  createdAt: string;        // 文档日期（报告/笔记创建时间）
  updatedAt: string;
}
```

> 该结构只存在于 **Hindsight retain 的元数据 + 本地映射表**，`KnowledgeDoc` 本身不需要建 records 表 —— 事实在 `research_reports`/`notes` 原表中，这里只存 `kind: "kb-index"` 的轻量映射（id ↔ sourceId ↔ 索引状态），用于去重与重建标记。

## 4. 索引内容策略（什么进向量，什么用结构化过滤）

只索引"**可检索的文本正文 + 少量结构化字段**"，不索引 PDF 二进制、不索引 JSON 外壳：

| 来源 | content 组装 | 结构化字段 |
| --- | --- | --- |
| `research_report` | 六段 sections（公司概况/财务/新闻/同业/估值/风险）序列化为 Markdown | symbolCode、rating、targetPrice |
| `note` | title + content；THESIS 附 status | symbolCode、noteType、thesisStatus |
| `briefing` | summary 要点 + content 正文 | date、market |
| `artifact` | artifact.summary + 文本正文 | kind |
| `pdf` | 走现有 PDF 管线（`pdftotext`）提取文本，取前 N 字符 | symbolCode（人工/标题识别） |

> Hindsight `retain` 天然做事实抽取与实体链接；我们**不重复做**抽取，只保证喂给它干净的原文。

## 5. 写入挂载点（增量，改动最小）

| 挂载点 | 改动 | 触发 |
| --- | --- | --- |
| `research.ts` 保存报告后 | 调 `KnowledgeBaseService.index(report)` | 研究任务成功 |
| `notes.ts` create/update/remove | `upsert` / `remove` | 笔记增删改 |
| `market-briefing.ts` | `upsert` | 简报生成成功 |
| `files.ts` / PDF 管线 | 可选 `index(pdf)` | 用户导入 PDF 研报 |
| 定时维护循环 | `reindex(owner)`（增量扫） | 兜底 + 存量迁移 |

写入统一走一个入口：

```ts
class KnowledgeBaseService {
  async upsert(owner, doc: Omit<KnowledgeDoc, "id">) {
    const id = sha256(`${owner}:kb:${doc.sourceKind}:${doc.sourceId}`);
    await db.put(owner, "kb-index", { id, sourceKind: doc.sourceKind, sourceId: doc.sourceId, indexedAt: now }); // 本地映射
    await hindsight.retain(`${owner}:kb`, buildRetainText(doc)); // 语义索引（幂等）
  }
  async remove(owner, sourceKind, sourceId) {
    await hindsight.deleteDocument(`${owner}:kb`, sha256(...)); // 删索引
    await db.remove(owner, "kb-index", id);                     // 删映射
  }
}
```

## 6. 检索 API（`routes.ts` 新增）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/knowledge/query` | 语义 + 结构化组合检索 |
| `POST` | `/api/knowledge/reindex` | 存量重建（分批幂等） |
| `GET` | `/api/knowledge/stats` | 文档数/按类型分布/上次索引时间 |

`/query` 请求与响应：

```ts
// 请求
{ q: "宁德时代电池毛利率趋势", symbol?: "300750.SZ", kind?: "research_report|note|…",
  from?: "2025-01-01", to?: "2026-11-23", limit?: 20 }
// 响应：每条命中带 sourceId，前端/对话据此回链原文
{ hits: [{ id, title, symbolCode, sourceKind, sourceId, score, snippet }], total }
```

服务端实现：

1. 先按结构化字段（symbol/kind/时间/rate）在本地 `records` 过滤出候选 `sourceId` 集；
2. 调 `hindsight.recall("{owner}:kb", q)` 语义召回；
3. 用候选集白名单裁剪 Hindsight 命中（与记忆系统 `memoryScope` 同一对齐模式）；
4. 无 Hindsight 时降级为关键词评分（复用 `memory-recall.ts` 思路）。

> 对话侧：Agent 想要参考历史研报时，通过一个轻量 `recall_knowledge` 工具调用同一服务，把命中正文注入上下文——这样"深研新标的前先看旧报告"成为可能。

## 8. 存量迁移（一次性 + 幂等）

```
reindex(owner):
  cursor = 读 kb-index 的最后迁移进度
  for kind in [research_reports, notes, agent-artifacts, market_briefings]:
    batch = db.list(kind, 按 createdAt 分页 N=200)
    for rec in batch:
      if 已索引（映射存在且 updatedAt 未变）→ skip
      upsert(owner, buildDoc(rec))     # 幂等 id
      db.put 映射标记
    更新 cursor；单批超时则暂停，等下一维护 tick 继续
```

规模预估：研报/笔记为万级，远小于记忆系统 ~1 GB 的存量压力，单用户秒级完成。

## 10. 边界与降级

- **Hindsight 不可用**：查询降级为结构化字段过滤 + 关键词评分（复用记忆 fallback 模式），不阻断原研报/笔记浏览。
- **PDF 无法解析**：跳过索引并记录，不阻塞其它文档。
- **隐私**：`kb-index` 与原始记忆一样按 `owner` 隔离，同步遵循 Supabase RLS；检索不跨账户。
- **不重复沉淀**：知识库只索引已存在的研报/笔记，不额外对 PDF 做二次 LLM 分析（那是 P1 财报解析的事）。
